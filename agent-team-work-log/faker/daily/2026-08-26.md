- OBD와 Graph는 “성장 타임라인 + 관계 그래프”를 붙인 구조보다, 자료가 판단으로 변환되는 `Operating Map`으로 설명하는 편이 IA가 더 자연스럽다.
- Graph 안에 있던 Dev Architecture 콘텐츠는 `Operating Map` 하위 콘텐츠 아래에 유지해 정보 손실을 막았다.
- 상단 구분은 여러 라인을 겹치기보다 섹션 시작/전환 지점에만 한 줄씩 남기는 편이 화면이 조용하다.
- OBD Map의 핵심은 텍스트보다 “자료가 판단으로 바뀌는 경로”이므로, static image가 아닌 React/CSS 인포그래픽으로 직접 렌더링하는 편이 유지보수와 반응형 대응에 유리하다.
- 모바일/태블릿에서는 복잡한 원형 배치를 유지하기보다, 단계 순서와 루프 복귀 표시가 분명한 카드형 흐름으로 낮추는 편이 가독성이 좋다.
- Chris가 “별로”라고 판단한 시각화는 더 복잡하게 살리지 말고, 정보 순서를 바로 읽는 스텝/화살표 구조로 낮추는 편이 맞다.
