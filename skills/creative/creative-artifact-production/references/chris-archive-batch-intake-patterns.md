# Chris Archive batch intake patterns

Use this reference when Chris sends many images with `추가해줘` in one Telegram turn, or a rapid sequence of visual references for the long-term Chris Archive.

## What changed in this session

Chris was adding many images in a row and specifically noticed that repeated progress fragments sounded like the assistant was “말을 하다 말어.” The working pattern should therefore be quiet, batched, and completion-oriented.

## Recommended large-batch workflow

1. Treat every image paired with `추가해줘` as approved for archive intake.
2. For 1–2 images: normal per-image analysis is fine.
3. For 3+ images in one turn:
   - Use a single combined pass for copy → entry → index → design-system draft → verification.
   - Keep each entry complete enough for later clustering, but shorter than the full single-image essay unless Chris explicitly asks for deep analysis.
   - In the Chris-facing reply, report the count, paths/cluster names at a high level, and the strongest shared DNA signals.
4. If a hash or visual duplicate appears, still save it when Chris says `추가해줘`, but mark it as related/supporting evidence rather than a wholly new cluster.
5. When images contain third-party names, artists, projects, service UIs, brands, or logos:
   - preserve the reference original,
   - mark brand-safety risk in the entry,
   - explicitly say future assets should extract principles only, not literal wording/identity.

## Completion reply shape

Use one concise completion message:

- `저장 완료했어, Chris.`
- number of images saved if batch
- mention `index.md` and `DESIGN_SYSTEM_DRAFT.md` updated
- 3–6 shared design-DNA bullets
- one caution if relevant: third-party text, generic AI glow, over-intense color, privacy/agency, accessibility, driving safety

Avoid sending progress fragments between every tool step unless there is a real blocker or an unusually long run.
