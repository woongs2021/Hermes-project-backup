# Chris Design DNA unified tab + GoYJ review pattern

Use when Chris asks to turn Chris Archive / Design DNA work into a webapp surface, especially after he says the result feels off, too fragmented, too analytical, or asks to merge tabs.

## Session lesson

When Design DNA was first split into multiple subtabs (`About Design DNA`, `Chris Design Archive`, `Agentic Brand & Package System`), Chris said it did not feel right and asked to make it one tab and run GoYJ review first. The issue was not that the analysis was wrong; the UI led with taxonomy/process instead of brand feeling.

## Preferred workflow

1. **Run GoYJ review before rebuilding the screen** when Chris expresses aesthetic dissatisfaction with Design DNA / archive / brand-system presentation.
2. Treat the review question as: what feels emotionally/visually wrong, what should be removed, and what single story should the page tell?
3. Prefer a **single scroll narrative** over multiple subtabs for Design DNA unless Chris explicitly asks for navigation.
4. Lead with a brand declaration, not the analysis machinery.
5. Move prompt/package/process language lower on the page and soften functional labels.
6. Verify with browser probes that the old subtab nav is gone, the unified story renders, and desktop/tablet/mobile do not overflow.

## Recommended single-page narrative

1. **Hermes declaration** — e.g. `헤르메스는 사람의 맥락을 보호하는 조용한 지능입니다.`
2. **Chris Archive Evidence** — explain what the system learned from the archive: not image style, but repeated judgment signals.
3. **Core DNA 3** — the emotional center:
   - Protected Human Context
   - Warm-Cool Intelligence
   - Quiet Signal Rhythm
4. **Expression Layer 3** — how the center becomes visual form:
   - Tactile Optical Material
   - Editorial Evidence System
   - Soft Object / Presence Mark
5. **First Asset Direction** — recommend `Hermes Presence Mark` before complex dashboard/package assets.
6. **Never Become** — concise guardrails: no generic AI-startup neon, robot/brain/surveillance metaphors, KPI pressure dashboard, copied third-party brand/text/layout, or overused chrome/liquid/rainbow effects.

## Copy/tone guidance

- Prefer: `quiet`, `protected`, `human context`, `presence`, `warm-cool intelligence`, `evidence`, `rhythm`, `OS-native`.
- Avoid leading with: `Agentic Brand & Package System`, `Prompt Package Ready`, `Generate assets`, `provider-independent`, `KPI`, `AI dashboard`, `AI가 사용자를 분석한다`, or anything that feels like an internal tooling dashboard.
- Frame prompt packages as an implementation layer, not the top-level brand story.
- Describe Chris Archive as a source of repeated visual judgment signals, not as a dataset that datafies Chris's taste.

## Verification checklist

- [ ] No Design DNA subtab nav remains if Chris asked for one tab.
- [ ] Page opens with a strong Hermes statement, not process/taxonomy.
- [ ] Chris Archive section explains `evidence → pattern → system`.
- [ ] Core DNA is visually higher priority than expression/prompt details.
- [ ] First asset recommendation is visible, with `Hermes Presence Mark` as the default first experiment unless Chris chose another asset.
- [ ] Existing Chris Archive count/assets still pass.
- [ ] Desktop/tablet/mobile show no horizontal overflow.
- [ ] Markdown download/popup still works if the document is exposed in the webapp.
