# Chris Archive batch intake clusters

Use this reference when Chris sends many visual references with `추가해줘` and the goal is long-term extraction into `DESIGN_SYSTEM.md`.

## Session learning

Chris often sends multiple archive images rapidly, sometimes several in one message. The correct behavior is to process them as a batch, work quietly, verify all files, then send one concise completion summary.

If the prior turn was interrupted, first finish any images that were already requested but not summarized, then process the new image(s). Mention both only in the final completion note.

## Batch workflow

For each image:
1. Generate a visual-DNA slug from what is visible, not from the cache filename.
2. Copy the original into `images/YYYY/MM/YYYY-MM-DD_<slug>_<sha12>.jpg`.
3. Create `entries/YYYY/YYYY-MM-DD_<slug>.md` with first-pass Karina analysis.
4. Append to `index.md`.
5. Add only tentative cluster-level candidates to `DESIGN_SYSTEM_DRAFT.md`.
6. Verify asset and entry existence/size before reporting success.

When several images arrive at once, a combined script pass is preferred: copy → write entries → update index → update draft → verify.

## Chris-facing completion format

Keep it short:
- “저장 완료했어, Chris.”
- For batches, list each image title with asset path + entry path.
- Summarize 3–6 strongest cluster signals total, or 2–4 per image if there are only two images.
- Mention `index.md` and `DESIGN_SYSTEM_DRAFT.md` were updated.
- Mention one important caution if applicable: third-party wording, generic AI glow, privacy/agency, accessibility, driving safety, or health-data evidence limits.

Avoid sending repeated progress fragments between tool steps. Telegram should mostly receive the final completion note unless there is a real blocker.

## Candidate clusters observed

Treat these as candidates, not final rules:
- Ambient companion OS: human hand/phone, floating cards, warm halo, privacy-safe personal state.
- Calm AI state components: dot matrix processing, glass progress bar, pause/stop affordances, honest progress labels.
- Luminous boundaries/containers: soft orb/squircle/capsule, chromatic rim, inner void, safe presence.
- Protected reveal: eclipse/contact, shadow over signal, privacy-safe emergence.
- Orbital/loop systems: helix, constellation, feedback orbit, resonance stack.
- Relational mesh fields: overlapping spheres, woven/halftone texture, warm-cool emotional/data layers.
- Human perception/signal: profile silhouette, lens metaphor, scanline/waveform identity; requires consent/agency framing.
- Circular navigation: thumb-safe circular content nodes, Explore pill, biomorphic content system; requires accessibility/usability checks.
- Product narrative cards: rounded bento/story decks, technical proof cards, architecture as story.
- Editorial/package systems: monochrome spreads, geometric poster fields, vinyl/archive objects, physical merch/toolkits.
- Pattern/support motifs: stripe density, purple phase-shift grids, reaction-token mosaics.

## Guardrails reinforced

- If reference includes third-party brand names, project names, logos, song/artist labels, or service names, archive it but mark brand-safety and extract only principles.
- Do not promote a single image into a final design rule; use cluster-level tentative language until GoYJ review or Chris approval.
- For personal metrics, emotional profiling, health/wellness, or human signal visuals, explicitly include privacy, consent, agency, correction, hide/delete, and overclaim/evidence restraint.
- For vehicle/cockpit references, include glanceability, distraction, brightness, motion speed, and safety restraint.
- If the same/near-duplicate visual appears again, save it when Chris says `추가해줘`, but mark it as supporting evidence rather than a new cluster.
