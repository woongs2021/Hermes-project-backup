# Chris Archive batch intake lessons

Use this reference when Chris sends many images in a row with `추가해줘` for long-term visual/design-system extraction.

## Session lesson

Chris values fast, quiet intake. During a long run of archive additions, repeated progress fragments like “분석했어, 저장할게” felt like the assistant was “말을 하다 만” 것처럼 보였다. The corrected pattern is:

1. Work quietly after the `추가해줘` trigger.
2. Use tools to save the asset, write the entry, update `index.md`, update `DESIGN_SYSTEM_DRAFT.md`, and verify both asset and entry exist.
3. Send one concise completion reply only after verification.
4. Mention paths + 3–6 strongest design-DNA signals + one caution if relevant.
5. Send an interim message only for a real blocker or unusually long-running operation.

## Long-session archive hygiene

- Keep entries comparable with the standard sections, but keep Chris-facing replies short.
- Do not treat every new image as a new core DNA axis. Some images are support evidence for an existing cluster.
- If the image is a crop/near-duplicate of a prior reference, say it reinforces that cluster and ask/mark whether it should be shortlist or supporting evidence during GoYJ review.
- Preserve third-party references, but never reuse literal brand names, slogans, logos, UI layouts, or proprietary product details in generated brand output. Extract principles only.
- For user-state/emotion/personality UI references, always carry privacy/agency/consent/correction/mute/delete cautions into the entry.
